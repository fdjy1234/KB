# 保險業 MIS 人員職能分級框架
## 系統開發人員 ↔ 系統分析師 雙軌發展模式

---

## 概述 (Overview)

本框架專為保險業內部 MIS（管理資訊系統）部門設計，涵蓋**系統開發人員（Developer）** 與 **系統分析師（System Analyst）** 從入門至首席級的完整職能分級體系。

### 框架特色
- **從 L6 開始即為雙軌設計**：入門級已區分開發與分析傾向
- **保險業特化**：融入保險業務特有需求（核保系統、理賠流程、精算、風險管理等）
- **靈活發展路徑**：允許同一職級內的跨軌道發展
- **實用工具齊全**：含職級進階 Checklist、角色定義、保險業務場景等

---

## L6 - Junior MIS 人員（入門級）

### 適用角色
- **開發軌道傾向**：Junior Developer / 程式設計師
- **分析軌道傾向**：Junior Analyst / 業務分析助理
- **通用基礎**：IT 新鮮人、應屆畢業生、轉職人員

---

### L6 - 系統開發傾向

#### 硬實力 (Hard Skills)
- **程式語言基礎**
  - 掌握至少 1 種主流語言（Java, C#, Python, JavaScript 等）
  - 能撰寫基本程式邏輯與控制流
  - 理解物件導向編程基礎概念

- **開發環境與工具**
  - 熟悉 IDE（Visual Studio, IntelliJ IDEA, VS Code 等）
  - 能使用 Git 進行版本控制（commit, push, pull, branch）
  - 能使用公司開發環境（本地、測試、預上線等）
  - 理解資料庫基本操作（SQL 基本 CRUD）

- **保險業務基礎**
  - 理解基本保險產品概念（壽險、產險、健險等）
  - 了解保險流程基礎（投保、核保、理賠基本流程）
  - 能閱讀業務規格書與流程文檔
  - 理解保險系統的主要功能模組（投保系統、理賠系統、核保系統等）

- **測試與品質**
  - 能撰寫簡單單位測試（Unit Test）
  - 能進行本地功能測試與基本 debug
  - 理解程式碼規範與編碼標準

#### 軟實力 (Soft Skills)
- 良好的學習態度，主動請教資深同仁
- 能清晰理解與執行分配的開發任務
- 主動報告進度與遇到的困難
- 能根據 code review 意見改進
- 具備基本的溝通與協作能力

#### 技術策略能力 (Technical Strategy)
- **開發範圍**：理解分層架構（UI/Business Logic/Data Access），能按規範完成功能
- **業務理解**：初步理解保險業務流程，能將簡單業務需求轉化為開發任務
- **品質意識**：理解單位測試的重要性，知道何時進行本地測試

---

### L6 - 系統分析傾向

#### 硬實力 (Hard Skills)
- **業務分析基礎**
  - 能理解並記錄簡單的業務流程
  - 能繪製基本流程圖（Flowchart, BPMN 簡單版）
  - 理解保險產品基本分類與特性
  - 能識別簡單的業務問題與改進點

- **保險業務知識**
  - 深入理解至少 1 種保險產品（壽險、產險、健險等）
  - 掌握該產品的完整業務流程（投保 → 核保 → 承保 → 理賠）
  - 了解相關的保險法規與監管要求
  - 理解產品定價、風險評估的基本概念

- **文檔與溝通**
  - 能撰寫簡單的業務需求說明
  - 能使用 Visio, Lucidchart 等工具繪製流程圖
  - 能進行簡單的業務訪談與需求收集

- **系統認知**
  - 熟悉公司主要業務系統（投保系統、理賠系統、核保系統等）
  - 能閱讀系統架構文檔
  - 理解系統資料模型基礎

#### 軟實力 (Soft Skills)
- 對保險業務有濃厚興趣與學習熱情
- 能與業務單位進行有效溝通
- 細心、邏輯清晰
- 主動學習保險業務與系統知識
- 能接受指導並快速改進

#### 技術策略能力 (Technical Strategy)
- **業務理解**：初步掌握保險業務邏輯，能識別業務改進機會
- **系統認知**：理解系統如何支撐業務流程
- **需求表達**：能用清晰的文字與圖表表達業務需求

## L7 - Intermediate MIS 人員（中階級）

### 適用角色
- **開發軌道傾向**：Software Engineer / 資深程式設計師
- **分析軌道傾向**：Business Analyst / 系統分析師
- **通用**：3-5 年經驗，能獨立完成模組級任務

---

### L7 - 系統開發傾向

#### 硬實力 (Hard Skills)
- **進階程式語言能力**
  - 精通至少 1 種主流語言，了解其生態與最佳實踐
  - 能運用常見設計模式（Strategy, Factory, Repository 等）
  - 理解並應用 SOLID 原則
  - 能撰寫清晰、可維護的程式碼

- **應用開發與架構**
  - 能設計模組化程式碼架構
  - 理解 MVC/MVVM/Clean Architecture 架構模式
  - 能進行資料庫設計（表結構、索引、規範化）
  - 能開發 API（REST、gRPC 等）與基本驗證機制
  - 理解非同步程式設計與事件驅動基礎

- **保險業務深度**
  - 深入理解至少 2 種保險產品的完整業務流程
  - 熟悉產品定價邏輯、核保規則、理賠流程
  - 理解保險監管要求對系統的影響（如資料保留、報表要求等）
  - 能在開發中考慮保險業務的複雜性與合規性

- **CI/CD 與自動化**
  - 能配置與維護 CI/CD pipeline（GitHub Actions, GitLab CI, Jenkins 等）
  - 能整合自動化測試與程式碼品質檢測
  - 能使用監控工具蒐集應用指標與日誌

- **測試策略**
  - 能撰寫單位測試、整合測試
  - 能設計測試案例並進行測試計劃
  - 理解測試金字塔與回歸測試概念

#### 軟實力 (Soft Skills)
- 能與業務單位、分析師、測試人員密切合作
- 主動提出技術可行性評估與風險點
- 能參與技術設計討論並提出觀點
- 願意分享知識與協助 mentor 新人
- 能將業務需求轉化為技術方案

#### 技術策略能力 (Technical Strategy)
- **架構參與**：能參與模組級架構設計決策，評估技術方案利弊
- **保險業務映射**：能將保險業務邏輯有效映射到系統設計
- **品質策略**：能提出測試覆蓋率改善建議，推動 Shift-left 測試
- **技術債**：能識別潛在的技術債並評估影響

---

### L7 - 系統分析傾向

#### 硬實力 (Hard Skills)
- **業務分析深度**
  - 能獨立分析複雜業務流程與系統功能需求
  - 能識別業務流程瓶頸與改進機會
  - 能進行風險識別與評估
  - 能提出業務流程優化方案

- **保險業務專業**
  - 精通至少 2-3 種保險產品的完整業務流程
  - 深入理解產品設計、定價、核保規則、理賠流程
  - 熟悉保險法規與監管要求
  - 能評估新產品或新流程的可行性與風險

- **需求管理與文檔**
  - 能撰寫詳細的系統需求規格書（SRS）
  - 能進行需求優先級評估與範圍控制
  - 能管理需求變更與影響評估
  - 能繪製複雜的業務流程圖（BPMN）與系統架構圖

- **系統認知**
  - 深入理解公司主要系統架構與資料流
  - 能識別系統集成點與依賴關係
  - 能評估現有系統能否支持新需求
  - 理解系統安全、性能、可用性要求

#### 軟實力 (Soft Skills)
- 能與多個業務單位進行有效溝通
- 能從業務角度提出系統改進建議
- 能進行跨部門協調與需求平衡
- 具備商務溝通與需求表達能力
- 能建立與業務單位的信任關係

#### 技術策略能力 (Technical Strategy)
- **需求策略**：能將業務目標轉化為系統需求與實現計畫
- **風險管理**：識別業務與系統風險，提出應對方案
- **系統規劃**：能參與系統升級、整合的規劃與評估
- **價值交付**：聚焦於業務價值實現與投資回報

## L8 - Senior MIS 人員（資深級 - 軌道深化點）

### 適用角色
- **開發軌道傾向**：Senior Developer / Tech Lead / 資深開發主管
- **分析軌道傾向**：Senior Analyst / Solutions Architect / 專案經理
- **通用**：5-8 年經驗，能主導中型專案或系統

---

### L8 - 系統開發傾向

#### 硬實力 (Hard Skills)
- **複雜系統開發**
  - 能設計跨系統整合方案（分散式系統、非同步通訊等）
  - 精通微服務架構與相應設計模式
  - 深入理解資料庫優化、查詢分析、索引策略
  - 能進行系統性能分析與優化（Profiling, Benchmarking）

- **保險業務系統設計**
  - 能設計支持複雜保險業務邏輯的系統架構
  - 深入理解保險核保引擎、定價引擎、理賠流程自動化等
  - 能處理保險業的高併發、高準確性要求
  - 能設計支持複雜業務規則與監管合規的系統

- **高級架構能力**
  - 能設計可擴展、高可用的應用架構
  - 理解事件驅動架構 (Event-driven) 與 CQRS 概念
  - 能進行架構層面的決策與 trade-off
  - 能設計系統容錯、災難恢復方案

- **DevOps 與基礎建設**
  - 精通 Docker / Kubernetes 容器化部署
  - 能設計與維護應用監控、日誌、追蹤體系
  - 理解基礎設施即程式碼 (IaC)
  - 能處理複雜運維場景（資料遷移、版本升級等）

- **安全與合規**
  - 理解常見安全漏洞（OWASP Top 10）與防護方式
  - 能進行安全程式碼審查
  - 理解保險業的安全與合規要求（資料保護、稽核日誌等）
  - 能設計符合監管要求的系統

#### 軟實力 (Soft Skills)
- 能領導中型功能或專案的技術實現
- 主動識別與解決技術瓶頸
- 能建立開發團隊內的技術標準與最佳實踐
- 善於跨部門溝通與協調
- 能進行技術方案決策與複雜 trade-off

#### 技術策略能力 (Technical Strategy)
- **系統設計決策**：主導模組級或專案級技術架構設計
- **保險業務支撐**：確保系統設計能有效支持複雜的保險業務邏輯
- **可測試性設計**：主動設計可測試的系統，與 QA 協作制定測試策略
- **效能與可靠性**：制定效能基準與優化計畫，設計高可用方案

---

### L8 - 系統分析傾向

#### 硬實力 (Hard Skills)
- **複雜業務分析**
  - 能進行企業級業務流程分析與重新設計
  - 能識別並評估複雜業務機會與風險
  - 能制定業務改進與數位化轉型方案
  - 能進行跨業務部門的流程整合規劃

- **保險業務專家**
  - 精通 3+ 種保險產品的完整業務流程與細節
  - 深入理解保險精算、風險管理、監管合規等高階概念
  - 能評估新產品開發的可行性與系統支持需求
  - 能進行保險業務流程設計與優化

- **系統架構分析**
  - 能進行企業級系統架構分析與規劃
  - 能評估現有系統能力與改進方向
  - 能識別系統集成需求與整合點
  - 能進行系統升級、整合的詳細規劃

- **需求管理與設計**
  - 能撰寫企業級系統需求規格書與功能設計文檔
  - 能進行複雜的需求優先級評估與範圍管理
  - 能進行需求變更管理與影響評估
  - 能設計詳細的系統資料模型與接口規范

- **項目管理基礎**
  - 能進行專案計劃、進度追蹤與風險管理
  - 能進行相關人員的協調與溝通
  - 理解專案預算與成本管理

#### 軟實力 (Soft Skills)
- 能領導專案需求分析與系統規劃
- 能建立與業務單位、技術團隊的有效溝通與信任
- 能進行跨部門協調與複雜利益平衡
- 具備強大的商務溝通與演講能力
- 能獨立承擔複雜專案的分析與規劃責任

#### 技術策略能力 (Technical Strategy)
- **業務策略**：能將保險業務目標轉化為系統需求與實現方案
- **系統規劃**：能進行企業級系統規劃與整合評估
- **風險管理**：識別並管理業務、系統、專案風險
- **價值交付**：確保業務價值實現與投資回報最大化

### L8 - Hybrid 混合傾向（同時具備開發與分析能力）

#### 硬實力 (Hard Skills)

- 能獨立進行：**業務需求分析 → 系統架構設計 → 技術方案實現 → 品質驗收**
- 能進行保險業複雜業務流程的設計與技術實現
- 能識別並優化業務流程中的技術瓶頸
- 能評估保險業務需求的技術可行性與成本

#### 軟實力 (Soft Skills)
- 能在業務與技術之間建立有效的橋樑
- 能進行業務驅動的技術決策
- 能領導跨職能的專案實現
- 具備雙向的溝通與影響力

#### 技術策略能力 (Technical Strategy)
- **端到端方案設計**：從業務需求到技術實現的完整規劃
- **保險業務映射**：在業務與技術架構之間建立有效映射
- **價值驅動**：聚焦於業務價值與技術可行性的平衡

## L9 - Staff MIS 人員（專家級 - 技術社群領袖）

### 適用角色
- **開發軌道傾向**：Staff Engineer / Engineering Manager / 技術部主任
- **分析軌道傾向**：Solutions Architect / Enterprise Architect / 業務發展經理
- **混合軌道傾向**：Tech Architect / IT Director（混合型領導）
- **通用**：8+ 年經驗，能主導企業級項目與系統

---

### L9 - 系統開發傾向

#### 硬實力 (Hard Skills)
- **企業級架構設計**
  - 能設計大型分散式系統，涵蓋多個服務與整合點
  - 精通高可用 (HA)、高併發、強一致性等複雜場景
  - 能進行系統重構與技術棧升級
  - 能設計支持保險業複雜業務的企業級架構

- **基礎建設與自動化**
  - 能設計並建立企業級 CI/CD 平台
  - 深入 Kubernetes、容器編排、GitOps 等運維技術
  - 能設計監控、日誌、追蹤的集中式平台
  - 能建立開發效能提升的自動化體系

- **技術卓越**
  - 在 1-2 個技術領域達到企業內頂級水準
  - 能進行技術決策的前期研究與預研
  - 對開源技術與行業趨勢有深入理解
  - 能推動公司的技術創新與現代化

- **保險業務系統專業**
  - 深入理解保險業系統架構與整體景觀
  - 能設計支持複雜保險業務邏輯的企業級架構
  - 能評估新技術對保險業務系統的影響

#### 軟實力 (Soft Skills)
- 能為整個技術組織設立技術願景與 roadmap
- 能指導多個開發團隊，提升整體技術能力
- 是技術文化推動者，能導入最佳實踐
- 能與高層管理層溝通技術決策與投資回報

#### 技術策略能力 (Technical Strategy)
- **企業架構規劃**：設計統一的技術棧與架構模板
- **品質治理**：制定企業級品質標準與評估指標
- **技術債治理**：識別、量化、償還企業級技術債
- **技術現代化**：推動技術棧升級與系統現代化

---

### L9 - 系統分析傾向

#### 硬實力 (Hard Skills)
- **企業級業務分析**
  - 能進行企業級業務架構分析與整體規劃
  - 能識別並評估複雜的跨業務機會與風險
  - 能制定保險業的數位轉型戰略
  - 能進行業務流程重新設計與組織優化

- **保險業務戰略**
  - 精通保險業的完整業務模式與價值鏈
  - 深入理解保險監管環境與風險管理框架
  - 能評估新保險產品或新業務方向的可行性
  - 能進行保險業務創新與轉型方案設計

- **企業架構設計**
  - 能進行企業級系統架構規劃與整合設計
  - 能評估現有系統景觀與現代化方向
  - 能識別系統整合機會與優化方案

## 保險業職能需求場景

### 典型保險業 MIS 人員工作場景

#### 開發軌道典型場景
1. **核保系統開發**：設計與實現複雜的核保規則引擎
2. **理賠流程自動化**：開發自動理賠判定與支付流程
3. **定價引擎**：實現保費計算與費率優化引擎
4. **資料大平台**：構建支撐精算與風險分析的資料倉庫
5. **監管報表系統**：開發滿足監管要求的報表與稽核系統

#### 分析軌道典型場景
1. **產品設計與上市**：分析新保險產品的可行性與系統需求
2. **業務流程優化**：優化投保、核保、承保、理賠等流程
3. **成本優化**：識別與優化業務流程中的成本點
4. **系統整合規劃**：規劃異系統整合與系統景觀優化
5. **數位轉型**：推動線上業務、自動化、資料驅動等轉型

#### 混合軌道典型場景（推薦）
1. **新產品數位化**：從產品設計 → 系統架構 → 技術實現的完整交付
2. **業務流程自動化**：從流程優化分析 → 系統設計 → RPA/自動化實現
3. **核心系統現代化**：從業務需求評估 → 架構設計 → 漸進式遷移
4. **資料驅動轉型**：從業務需求分析 → 資料架構設計 → 平台建設
5. **客戶體驗優化**：從客戶旅程分析 → 系統設計 → 數位體驗交付

## 跨軌道轉換指南

### L6-L7 階段：保持通用基礎
✅ **推薦做法**：
- 既要熟悉程式碼與系統架構，也要理解保險業務
- 交叉輪崗：開發人員參與需求分析、分析師參與系統設計
- 重點培訓：保險業基礎知識、系統架構、業務流程

### L7-L8 階段：軌道專業化開始
✅ **何時保持混合軌道：**
- 對業務與技術都有濃厚興趣
- 善於跨職能溝通與協作
- 能處理複雜的業務-技術決策

✅ **何時轉向開發軌道：**
- 對技術深度有極強熱情
- 追求系統架構與技術卓越
- 想建立技術平台與基礎設施

✅ **何時轉向分析軌道：**
- 對保險業務與創新有濃厚興趣
- 追求業務價值與商業機會
- 想推動業務優化與轉型

### L8-L9 階段：企業級領導
✅ **L8 → L9 的跨軌道轉換：**
```
L8 Developer      →  可升至 L9 Hybrid/Staff Eng
L8 Analyst        →  可升至 L9 Hybrid/Solutions Arch
L8 Hybrid (推薦)   →  直升 L9 Tech Architect ⭐
```
- 轉換期：6-12 個月能力補強與實踐
- 輔導機制：引入外部顧問或借調到合作單位

## 人才培養與發展建議

### L6-L7 階段培養重點
1. **技術基礎**：程式語言、開發工具、基本架構
2. **保險業知識**：產品、流程、法規、市場
3. **軟技能**：溝通、協作、學習能力
4. **方向探索**：嘗試不同角色，發現興趣與優勢

### L7-L8 階段培養重點
1. **技術深化**（開發軌道）：架構設計、高級語言特性、DevOps
2. **業務專業化**（分析軌道）：保險產品深度、流程優化、項目管理
3. **雙向能力**（混合軌道）：程式碼 + 業務流程 + 系統設計
4. **領導力初級**：帶人、溝通、決策能力

### L8-L9 階段培養重點
1. **企業級思維**：業務對齁、戰略規劃、風險管理
2. **領導力深化**：團隊建設、文化推動、跨部門協調
3. **業界影響力**：知識分享、業界活動、品牌建設
4. **創新驅動**：技術/業務創新、轉型領導

### L9-L10 階段培養重點
1. **企業戰略**：制定 3-5 年發展戰略與 OKR
2. **領導力頂級**：企業級決策、組織建設、文化塑造
3. **業界領袖**：行業影響力、生態建設、創新引領
4. **傳承機制**：建立 L9 梯隊、知識沉澱、文化傳承

### 推薦培養路徑
```
【入門 L6】
├─ 新人培訓（3 個月）：基礎技術 + 保險業基礎知識
├─ 師徒制（1 年）：指派 mentor，進行日常指導
├─ 輪崗試驗（6 個月）：短期經歷開發與分析角色
└─ 方向確認（L6 結束）

【進階 L7】
├─ 軌道深化培訓（6 個月）
├─ 實戰項目（1-2 年）：主導或主要參與 1+ 個項目
├─ 領導力初級課程
└─ L7 完成後進行軌道專業化決策

【資深 L8】
├─ 企業級項目領導
├─ MBA/專業認證（可選）
├─ 領導力與管理課程
├─ 跨軌道嘗試（如有需要）
└─ L8 完成後評估 L9 潛力

【專家 L9】
├─ 企業戰略與規劃課程
├─ 行業高管培訓
├─ 國際交流與學習
├─ 搭建 L8 梯隊
└─ 制定 L9-L10 發展計畫

【首席 L10】
├─ 董事會/高管決策參與
├─ 行業戰略與發展論壇
├─ 下一代領袖培養
└─ 企業文化與願景塑造
```

## 績效評估與晉升決策

### 評估維度（360 度評估）
1. **自我評估**：對照職級標準進行自評
2. **主管評估**：直屬主管評估與建議
3. **同儕評估**：跨團隊同仁的認可度
4. **下屬評估**：帶領人員的反饋（L8 以上適用）
5. **客戶評估**：業務單位或內部客戶的滿意度

### 晉升決策流程
1. **符合條件判斷**：是否達到職級 Checklist 要求
2. **能力評估面試**：針對關鍵能力進行深入評估
3. **績效審查**：近期績效與貢獻評估
4. **發展潛力**：是否有更高職級的發展潛力
5. **晉升決議**：由人資與部門主管聯合決議

### 晉升失敗後的處理
- 制定明確的改進計畫（3-6 個月）
- 指派導師進行針對性培養
- 定期檢查進度與調整方案
- 一年後可以重新評估

## 備註

1. **職級評估不僅看年資**：職級反映實際能力與貢獻，年資只是參考因素
2. **跨越晉升**：在特定領域表現優異的人員可以加速晉升（如優秀開發者可直升 L8）
3. **軌道靈活性**：鼓勵在 L8 前保持廣泛嘗試，L8 後允許必要時的軌道轉換
4. **持續發展**：即使選擇特定軌道，也應保持對其他領域的學習與理解
5. **企業適配**：本框架應根據企業實際狀況進行調整與優化
6. **保險業特性**：框架已融入保險業務特有的複雜性、監管要求、風險管理等特點
7. **混合軌道推薦**：在保險業，混合型人才（業務+技術）更能推動數位轉型與創新

## 附錄：常見問題解答 (FAQ)

### Q1: 如何判斷自己應該走開發軌道還是分析軌道？
**A:** 可從以下角度考慮：
- **開發軌道**：喜歡解決技術問題、追求程式碼品質、喜歡深度技術研究
- **分析軌道**：喜歡解決業務問題、追求流程優化、喜歡與業務溝通
- **混合軌道**：兩者都感興趣，能很好地整合業務與技術

### Q2: 是否可以在軌道之間轉換？
**A:** 可以，特別是在 L7 之前。L8 後轉換需要 6-12 個月的能力補強。建議與主管討論轉換計畫。

### Q3: 混合軌道是否更容易晉升？
**A:** 不一定。混合軌道對個人能力要求更高，但在保險業 IT 中更稀缺，也更容易找到符合需求的項目。

### Q4: 如何從 L8 晉升到 L9？
**A:** 需要展現企業級的領導力與戰略思維，通常包括：
- 主導 1+ 個大型項目或平台建設
- 建立與培養技術或業務團隊
- 推動組織級的標準化或流程改善

### Q5: L9 與 L10 的區別是什麼？
**A:** 
- **L9**：企業級專家，能制定與執行部門級或產品線級的戰略
- **L10**：企業決策層，能制定與執行企業級戰略，對公司整體方向有影響力

### Q6: 如何持續提升專業能力？
**A:** 建議：
- 定期參加培訓與認證課程
- 閱讀行業資料與技術文章
- 參與行業論壇與社群
- 輪崗或短期項目以拓展視野
- 定期與導師或同儕進行成長討論
